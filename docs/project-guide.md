# MarkFlow 项目说明书

版本：0.1.0 · 更新日期：2026-10-02 · 阶段：首版实现与平台验证

项目名称暂用 **MarkFlow**。本文保留确认需求、首期范围及建议验收标准；当前实现与实际测试结果分别见 [技术开发说明书](technical-design.md) 和 [验证记录](verification.md)，启动方式见 [README](../README.md)。需求清单中的“已确认”指需求来源，不等于所有平台均已验收。

## 1. 项目目标

开发一款运行于 Windows 和 macOS 的本地 Markdown 编辑器。用户选择本机文件夹作为工作区，在左侧管理真实目录与 Markdown 文件，在右侧通过多标签页阅读、编辑文档。编辑内容实时呈现，并自动保存回原文件。

目标用户为使用 Markdown 编写个人笔记、技术文档和日常资料的个人用户。该用户画像属于建议，不影响已确认的功能范围。

核心原则：

- 工作区对应系统中的真实文件夹，目录对应其子文件夹，文档对应相同位置的 `.md` 文件。
- Markdown 文件是正文的最终存储形式；用户可以用系统文件管理器和其他编辑器访问这些文件。
- 主界面保持简单：工作区树、标签页、正文区域、可收起的大纲，以及设置入口。
- 文档编辑、预览和本地保存可以离线完成。
- 保存失败、文件被外部修改等情况必须可见，不能把尚未写入磁盘的内容显示为“已保存”。

## 3. 主界面与编辑体验

```text
┌─────────────────────────────────────────────────────────────────────┐
│ MarkFlow                                    视图切换        设置       │
├───────────────┬─────────────────────────────────────┬───────────────┤
│ 工作区        │ 文档 A ×   文档 B ×                 │ 大纲          │
│ ▾ Note        ├─────────────────────────────────────┤ 1 标题        │
│   ▾ 技术      │                                     │   1.1 子标题  │
│     Vue.md    │  正文编辑或预览                     │ 2 标题        │
│   日记.md     │  分屏时：左侧源码 / 右侧预览        │               │
│ ▾ Writing     │                                     │               │
│   随笔.md     │                                     │               │
├───────────────┴─────────────────────────────────────┴───────────────┤
│ 当前文件路径                                  已保存 / 保存失败    │
└─────────────────────────────────────────────────────────────────────┘
```

这是信息布局草图，不是最终视觉设计。建议左侧栏与大纲可收起、宽度可调整；窄窗口下优先保留正文空间。没有工作区时展示“添加工作区”；有工作区但没有活动文档时显示打开或新建文档的入口。

### 3.1 四种视图

| 视图 | 用户可见行为 | 是否编辑正文 |
| --- | --- | --- |
| 所见即所得 | 正文直接呈现 Markdown 排版，用户在正文中编辑；输入 Markdown 标记可实时转换，体验接近 Typora | 是 |
| 源码 | 显示 Markdown 原文，适合查看和精确修改语法 | 是 |
| 分屏 | 左侧 Markdown 源码，右侧实时预览；建议分隔线可调整 | 在源码侧编辑 |
| 纯预览 | 仅呈现排版后的内容，适合阅读 | 否 |

本项目的“所见即所得”指上述直接编辑排版正文的体验。内核的即时渲染与富文本模式属于技术选型细节，不在产品里增加第五种视图。

设置中可以选择默认编辑视图，建议默认所见即所得。单篇文档可以临时切换视图；全局默认值用于首次打开文档。纯预览也是可选视图，但不接受正文输入。

视图切换使用同一份文档内容，不能清空尚未保存的修改。仅打开、阅读或切换视图不应触发文件改写；实际编辑后的格式规范化行为须经过兼容性验证。

## 5. Markdown 支持边界

“全面的标准语法”在本项目中具体定义为 CommonMark 基础语法及 GFM 扩展，避免把任意非标准扩展视为首期承诺。规范参考 [CommonMark](https://spec.commonmark.org/) 与 [GFM](https://github.github.com/gfm/)。

| 类型 | 首期支持内容 |
| --- | --- |
| 标题与段落 | ATX 的 H1–H6、Setext 标题、普通段落、软换行与硬换行、分隔线 |
| 行内格式 | 强调、加粗、行内代码、反斜杠转义、字符实体 |
| 列表与引用 | 有序列表、无序列表、嵌套列表、块引用及嵌套引用 |
| 代码 | 缩进代码块、围栏代码块、语言标记；建议支持常见语言高亮，未知语言按纯代码呈现 |
| 链接与图片 | 行内链接、引用式链接、自动链接、行内/引用式图片、相对路径资源 |
| GFM 扩展 | 表格及列对齐、任务列表、删除线、扩展自动链接 |
| HTML | 识别规范中的行内 HTML 和 HTML 块；显示安全过滤后的结果，正文源码保留 |

HTML 显示规则属于建议方案：允许安全的常见排版标签，阻止脚本、事件处理器、嵌入网页及危险地址。过滤只影响显示结果，不应擅自删除 `.md` 原文。数学公式和 Mermaid 首期按普通文本或代码处理。

所见即所得内核若无法无损编辑某类原始语法，必须允许在源码视图操作并保留原文，不能静默丢弃节点。具体兼容行为在编辑器验证阶段记录。

## 6. 数据与文件操作规则

### 6.1 工作区与文件树

- 添加工作区只注册已选择目录，不复制已有文件。
- 建议文件树显示所有普通目录和 `.md` 文件，扩展名匹配不区分大小写；图片等附件通过正文使用，不作为可编辑文档列出。
- 建议目录在前、文档在后，采用自然名称排序；空目录仍可显示。
- 重复添加相同真实目录时激活已有工作区。建议首期不添加父子重叠工作区，以减少重复展示。
- 工作区被删除、磁盘卸载或无读取权限时显示“不可访问”，保留注册信息，允许重试或移除。
- 移除工作区应先处理其未保存文档，再关闭相关标签；移除入口不等于删除文件夹。
- 建议首期不跟随符号链接、目录联接等特殊目录；可以显示受限提示，防止循环或越出工作区。

### 6.2 新建、重命名与移动

- 新建文档自动补齐 `.md` 后缀；名称校验兼顾 Windows 与 macOS，阻止路径分隔符、保留名称、非法字符及同名对象。
- 操作失败时保留原文档及当前编辑内容，树和标签不能提前显示成功。
- 操作包含打开且已修改的文档时，先完成保存；保存失败时允许取消操作或另存副本，不能继续改变路径。
- 文件夹重命名或移动时，其所有打开后代文档的路径同时更新。
- 建议移动仅处理同工作区。针对应用管理的附件，调整被移动文档中的相对引用；其他相对链接可能受影响，显示结果提示。首期不承诺自动修复整个工作区的所有入站链接。

### 6.3 删除

- 删除入口明确说明会影响真实磁盘文件，目录删除包含所有子对象。
- 先处理受影响文档的未保存修改，再确认删除；成功进入回收站后更新树并关闭对应标签。
- 外部删除已打开文档时保留内存内容并提示“文件已被删除”，提供另存副本；暂停向原路径自动写入，避免未经用户操作重新创建文件。
- 系统回收站不可用或操作失败时，不退化为永久删除。

### 6.4 图片与相对路径

建议默认在工作区根目录下使用 `assets/` 保存图片；文件名使用不冲突的标识，附件目录名可在后续设置中扩展。

例如，工作区为 `D:\Note`，文档为 `D:\Note\技术\Vue.md`，图片保存为 `D:\Note\assets\img-001.png`，正文插入 `![图片](../assets/img-001.png)`。Markdown 链接统一使用 `/` 分隔符，路径相对当前文档解析。

- 只有附件实际写入成功后才插入链接；文档只读或路径失效时不开始导入。
- 不把操作系统绝对路径写入新导入图片的 Markdown 链接。
- 建议 PNG、JPEG、GIF、WebP 为首期导入格式，默认单张上限 20MiB；具体限制待实现验证。
- 图片无需上传服务器；不会自动删除可能被其他文档引用的附件。
- 搬移整个工作区且保留目录结构后，文档与图片仍应可用；单独拷贝 `.md` 时需同时带走引用的附件。

## 7. 自动保存、冲突与恢复

### 7.1 正常保存

1. 用户编辑，正文与预览实时更新，状态变为“待保存”。
2. 建议停止输入约 500ms 后保存；持续输入约 2s 提交一次已完成的内容快照。
3. 写入过程中显示“保存中”；只有磁盘写入成功才显示“已保存”。
4. 保存过程中发生新输入时仍保留待保存状态，继续提交新版本。
5. 切换标签、失焦或关闭窗口前立即尝试保存；建议 `Ctrl+S` / `Cmd+S` 立即提交。

实时保存不表示每个按键都进行一次磁盘写入。中文输入法组合期间不通过重建编辑器打断输入，完成组合后再调度正文提交。

### 7.2 保存失败

权限不足、磁盘已满、文件被占用或工作区失联时，保留编辑内容，显示可理解的失败原因，并提供重试、复制内容或另存副本。关闭失败文档时需要用户选择处理方式，不能默默丢弃。

### 7.3 外部修改冲突

建议在检测到“当前编辑基准与磁盘内容不同”时暂停自动写入。用户可以重新加载磁盘版本、把当前内容另存副本，或明确选择覆盖磁盘版本。重新加载会放弃本地未保存修改，覆盖前应保留磁盘版本的恢复副本。

文件监听用于及时发现变化，保存前还应检查磁盘版本；不能仅靠监听宣称不会冲突。若用户用云盘或其他软件同时修改文件，也使用同一冲突规则。

### 7.4 异常恢复

建议将尚未成功写入原文件的草稿同步写入应用本地恢复区。异常退出后展示恢复列表，由用户选择恢复、另存或丢弃。恢复区写入失败应可见；不能承诺恢复从未成功持久化的最后一次输入。

建议恢复草稿和冲突副本保留 7 天，已成功提交且不再需要的草稿可清理。恢复数据也只保存在本机，具体保留策略属于建议。

| 编辑 | 默认视图 | 默认所见即所得；可选择源码、分屏、纯预览 |
| 布局 | 大纲显示与面板宽度 | 建议记住用户选择，默认显示大纲 |
| 文档 | 文档显示样式 | 默认标准模式，正文居中约 760px；超宽模式使用可用内容区宽度，保留必要边距 |

建议字号范围为 10–36px。字体选择建议从可用系统字体中提供常见选项，或允许输入字体名称并显示回退预览。主题与字体设置立即预览、持久化；提供恢复默认值。

设置只影响显示及操作偏好，不改写 Markdown 文件内容。具体预设颜色、字体选择方式和排版间距可在界面实现阶段决定。

## 9. 主要操作流程

### 9.1 开始使用

1. 安装并启动应用，点击“添加工作区”。
2. 在系统目录选择器中选择 `D:\Note`，或 macOS 上的某个笔记文件夹。
3. 左侧出现工作区及真实目录；展开目录，点击 `.md` 文档。
4. 文档在标签页中打开，按默认视图显示；点击标题旁的视图入口可以切换。
5. 修改内容，观察保存状态变为“已保存”，随后可在系统中查看同位置的 `.md` 文件。

### 9.2 编写包含图片的文档

1. 选中目录，新建文档并输入内容。
2. 粘贴截图或拖入图片；导入成功后显示图片并插入相对链接。
3. 在分屏视图核对源码与效果，用右侧大纲跳转到章节。
4. 打开其他文档建立更多标签，切换时各文档保持独立内容。

### 9.3 整理目录

在文件或目录的菜单中执行新建、重命名、移动或删除。移动先选择目标目录，删除先确认真实文件范围。操作完成后文件树与标签同步更新；建议提供“在系统文件管理器中显示”的辅助入口。

### 9.4 调整阅读与编辑环境

打开设置，调整主题色、亮暗模式、字体、字号与默认编辑视图。返回正文即可看到效果；重启应用后配置仍保留。

## 10. 质量、隐私与验收

### 10.1 建议质量目标

- 常用的本地 1MiB 以内 Markdown 文档，预览一般在完成输入后 150ms 内更新；以实际双平台测试结果为准。
- 含约 10,000 个条目的工作区按目录展开读取，避免启动时完整扫描阻塞界面。
- 较大文档或密集图片应提供加载提示和降级策略；建议超过 5MiB 时提示，超过 20MiB 先确认加载，具体阈值待验证。
- Windows 与 macOS 均验证中文输入、快捷键、缩放、文件路径、回收站、暗色和多标签切换。
- 保持键盘可操作、焦点可见、设置标签明确，颜色不作为保存失败的唯一提示。

### 10.2 隐私与资源访问建议

首期不上传正文、附件、绝对路径或恢复草稿，日志不记录正文。文档中的网络图片会请求外部服务器，建议默认禁用自动加载，并允许用户手动加载；此限制不影响本地附件。

普通远程网页只在用户点击后打开系统浏览器。文档不能执行脚本或调用应用的文件操作接口。本地图片与链接优先限定在已添加工作区内；越界资源显示提示，不自动开放整块磁盘访问。

### 10.3 首期验收路线

准备两个真实工作区、嵌套目录、重复标题、中文和空格路径、完整语法样例以及带相对附件的文档。分别在 Windows、macOS 完成添加工作区、文件操作、四视图切换、多标签编辑、图片导入、大纲跳转、设置持久化。

再模拟无权限、磁盘不可用、外部改写、外部删除、保存中继续输入和异常退出。任何一项造成静默覆盖、内容丢失、串写文档或误删真实文件，均应阻止首期发布。

## 12. 本轮完善范围（2026-10-02）

按用户选择实现第 1、4、5、6 项：搜索替换、编辑体验、导出和性能细节；第 2 项历史版本界面、第 3 项附件管理界面暂缓。原有自动恢复和图片导入继续可用。

- 当前文档查找替换支持字面量、区分大小写、Unicode 正则、上一处 / 下一处、单项 / 全部替换。匹配位置在源码中选中；替换会经过相同保存协调器。正则最多 5000 个匹配，独立线程搜索超过 1 秒中止。
- 工作区全文搜索显示文件、所属工作区、行号和上下文，包含已打开文档尚未保存的内容。点击结果打开源码并定位。快速打开按文件名或路径匹配，支持方向键与 Enter。
- 专注模式临时隐藏头部、侧栏和大纲，退出恢复原偏好。分屏按滚动比例同步，可在文档设置中关闭。
- 表格编辑窗口选择已有表格或在文末插入，支持增删行列并保留列对齐；代码块支持选择现有围栏、修改语言及内容、在文末插入。窗口打开后正文变化会拒绝应用，避免覆盖新内容。
- 状态栏显示字符数或选中字符数，统计悬浮提示字词数与预计阅读时间。
- PDF 支持 A4 / Letter、页边距、系统字体与字号、页码。独立 HTML 内嵌图片；ZIP 保留工作区内的 Markdown 与图片相对路径。缺失图片或越界资源阻止导出并提示。
- 文件树每级初始显示 80 项，手动加载下一批；当前文档所在条目保持可见。大纲与阅读统计使用后台线程，预览防抖，未使用的编辑视图不重复渲染，后台可视化实例闲置 60 秒后释放。
- 超过 512000 字符的文档切到源码编辑；超过 2MiB 的文档使用源码视图。工作区搜索结果最多 300 项、遍历最多 20000 个条目、最多 3 秒；全文搜索跳过超过 2MiB 或无法读取的文件，并提示截断与跳过数量。

PDF 使用图像分页，文字不支持选择复制；导出上限 100MiB、PDF 100 页。真实 Mac、完整规范语料、超大规模工作区及系统字体差异仍需发布前验收。

## 13. 归档、标签与行高（2026-10-03）

- 文档菜单使用“归档”，底部回收站可切换工作区。文档保存在所属工作区隐藏的 `.markflow-archive` 目录，不进入系统回收站；恢复到原路径，同名时生成“（恢复1）”等名称，避免覆盖。彻底删除需确认并直接删除归档正文；共用图片附件保留。
- 文档标签显示在文章路径旁，通过标签图标选择或添加。标签使用 YAML front-matter 的 `tags` 字符串数组；源码可查看全部元数据，可视化和预览显示正文。修改标签保留其他字段与注释；无效 YAML 会拒绝修改，需先修正源码。
- 设置 → 文档设置管理标签名称。重命名或删除同步更新所有已添加工作区的普通及归档文档，更新前保留原文件备份。未添加的工作区不参与同步；工作区不可用或文件冲突会中止操作。
- 正文行高默认 1.9 倍，可选 1.4–2.5 倍的常用值，应用于可视化编辑和预览。源码继续使用代码排版。
