# 首个测试版验收

测试版本：0.1.0-beta.1，Windows x64。

## 安装与数据

1. 从 https://yeyongzhi.github.io/MarkFlow/download 下载安装包。
2. 选择独立安装目录，例如 `D:\Program\MarkFlow`。
3. 添加一个用于测试的笔记文件夹，创建文档并添加标签。
4. 修改主题、字体和保存设置，退出后重新打开，确认偏好和标签保留。
5. 在“设置 → 保存与备份”打开数据目录，确认指向安装目录的 `data`。

不要直接安装到 `D:\Program` 根目录。正文与附件保留在选择的工作区；应用数据目录保存工作区登记、偏好、草稿、历史和备份。自定义备份目录会覆盖默认备份位置。

## 检查更新

在“设置 → 通用 → 关于 MarkFlow”点击“检查更新”。首版尚无更高版本时，应提示已经是最新版本。

beta 版可以更新到后续 beta 或更高的正式版；正式版不接收 beta。发布 beta.3 后，需要从已安装的 beta.2 验收下载、安装、重启和原数据保留。单元测试与签名验证不替代真实安装升级验收。

## 卸载

普通卸载应保留安装目录的 `data`；勾选删除应用数据应删除它。仅使用测试数据验证删除选项。工作区里的 Markdown 正文不随应用卸载删除。

## 维护者必须备份的文件

本地更新私钥位于项目根目录的 `.local/updater.key`，公钥文件是 `.local/updater.key.pub`。私钥已加入 Git 忽略规则，并配置到仓库 Actions Secret `TAURI_SIGNING_PRIVATE_KEY`。

请将私钥备份到加密存储或密码管理器，不要提交到 Git、放到网站或发送到聊天。后续版本继续使用同一把密钥，否则已安装版本不能验证新的更新包。

## 后续发布

1. 在 dev 上完成改动，将版本同步为 `0.1.0-beta.3`，更新 CHANGELOG。
2. 测试通过后提交推送，并将改动合并到 main。
3. 推送对应的 `v0.1.0-beta.3` 标签。
4. 等待 Release 工作流生成签名安装包、签名文件、`latest.json` 和校验文件。
5. 验收后公开预发布 Release，并检查网站直链和 beta.1 的应用内更新。

仓库默认分支保留 dev；Pages 从 main 部署。
